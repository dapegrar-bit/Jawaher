# جواهر ميزان — وثيقة المعمارية للتطوير v0.1

## الهدف
إصدار MVP للتجربة المحلية فقط: تسجيل حساب وإنشاء منشأة، دليل حسابات، مسودات قيود، ترحيل، ميزان مراجعة، سجل أحداث. لا يوجد إصدار فواتير متوافقة مع ZATCA أو تكامل بنكي أو ذكاء اصطناعي في الإصدار الحالي.

## المكونات
- `web/`: تطبيق Next.js App Router باللغة العربية وRTL.
- `api/`: NestJS REST API مع scrypt وكوكي جلسة HttpOnly، وصلاحيات `owner/accountant/viewer` (للتطوير؛ واجهة إدارة عضويات غير منفذة).
- `db/`: PostgreSQL مع علاقات مركبة تقيد ارتباط الحسابات والقيود بالشركة، ومنع التعديل بعد الترحيل، والتحقق من توازن القيد على مستوى قاعدة البيانات.
- `preview/`: معاينة مستقلة ببيانات مصطنعة؛ لا تتصل بالخادم ولا تستعملها كبرنامج محاسبة.

## دورة حياة القيد
1. تسجيل دخول بجلسة غير قابلة للقراءة من JavaScript عبر HttpOnly cookie.
2. اختيار منشأة تنتمي إلى مستخدم لديه صلاحية كتابة.
3. التحقق من التاريخ والفترة المفتوحة والحسابات الفعالة والمبالغ الدقيقة.
4. إدراج القيد كمسودة داخل معاملة PostgreSQL واحدة، مع مفتاح لمنع التكرار.
5. ترحيل القيد من خلال معاملة واحدة تستخدم `SELECT FOR UPDATE` على القيد والفترة، ثم تفحص الرصيد وتعدّل الحالة وتكتب سجل تدقيق.
6. PostgreSQL يطبّق trigger حماية للقيود المرحلة وconstraint trigger مؤجل للتحقق من توازنها عند الالتزام بالمعاملة.
7. ميزان المراجعة لا يقرأ إلا `status='posted'` وتاريخ القيد المحدد.

## نطاق العزل
تتحقق كل مسارات API ذات البيانات من عضوية المستخدم للشركة قبل القراءة أو الكتابة. بعض جداول المعاملات تستخدم مفاتيح أجنبية مركبة `(company_id, id)` لتقليل احتمال الخلط. هذه بنية تطوير وليست ضمانًا كاملًا لعزل متعدد المستأجرين؛ قبل النشر الفعلي يلزم إضافة PostgreSQL RLS، واختبارات تسرب بين الشركات، وحساب قاعدة بيانات بصلاحيات محدودة، ومراقبة مستقلة، وتقييم اختراق.

## متطلبات خاصة قبل الاستخدام التجاري
- الالتزام بمواصفات ZATCA وتدفقات التخليص/الإبلاغ وختم XML، وليس مجرد PDF أو QR.
- تصميم معتمد لرد القيد وإقفال الفترة والقيود الافتتاحية والتدفق النقدي والتقارير وفق السياسات المحاسبية المحلية.
- الضرائب متعددة المعالجات، وباقات الفواتير، والمرتجعات، وأرقام المستندات، والمطابقة البنكية، والتسويات.
- تعدد العملات، أسعار الصرف، التدقيق والتجزئة immutable audit log خارج قواعد البيانات التشغيلية.
- استضافة آمنة، إدارة أسرار، ضوابط مكافحة brute-force، MFA، فحص أمني، نسخ احتياطية واختبار استعادة.
- معالجة انتهاء الجلسات وتدويرها، تقييد التكرار على تسجيل الدخول، التحقق من سياسة كلمة المرور، سياسات الخصوصية والاستجابة للحوادث.
- نظام ترحيل قواعد بيانات versioned migrations، مراجعة طرق حذف/إلغاء الحسابات، وإضافة اختبارات تحميل.

## ضمان الجودة
- اختبار الحساب الدقيق بوحدات أصغر من الريال.
- رفض القيد غير المتوازن والسطور التي تحمل مدينًا ودائنًا معًا.
- منع إعادة ترحيل القيد أو تغييره بعد الترحيل.
- اختبار صلاحيات الحسابات والشركات والفترات.
- اختبار تكامل حقيقي مع PostgreSQL وNestJS (smoke test يتطلب تشغيل Compose).

## تصميم التكاملات المقبل
**جواهر جسر** مكون منفصل يستهلك واجهات Wafeq/Xero/ERPNext/Odoo عند الموافقة، ويدير جداول `external_system`, `external_id`, `internal_id`, `sync_cursor`, `sync_attempts` ويضمن عدم دخول بيانات المصدر إلى دفتر الأستاذ بلا سياسة اعتماد. لم يُنفذ بعد، ولا يجوز وصف موصلات الجهات الخارجية بأنها جاهزة.
