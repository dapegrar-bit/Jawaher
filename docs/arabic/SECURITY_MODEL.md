# نموذج أولي للعزل والحماية

تمهيد: هذا النموذج يحتاج تدقيقًا خارجيًا قبل التعاقد أو استقبال بيانات حقيقية.

- جلسة HTTP-only cookie، وطلبات تغيير الحالة تتطلب ترويسة تطبيق مخصصة وتحققًا من Origin. ليست بديلًا كاملًا عن إطار حماية CSRF إنتاجي.
- يستخدم الخادم `company_id` مع كل استعلام بيانات ضمن الوحدات المطبقة، ويستخرج العضوية من قاعدة البيانات عند كل طلب.
- الأدوار: `owner`، و`accountant`، و`viewer`، ويمكن للمالك إغلاق الفترة فقط.
- كلمات المرور scrypt مع ملح فريد؛ ينبغي إضافة MFA وحدود المعدلات والتجديد والإبطال وإشعارات الدخول ومراقبة الاختراق.
- PostgreSQL يعتمد على قيود FK مركبة `(id,company_id)` في المستندات ومعظم روابط الوحدة المالية. يستلزم تقييم RLS واختبارات انفصال مستأجرين قبل الإنتاج.
- لا تُحفظ مفاتيح واجهات البرامج المنافسة في الإصدار الحالي، ولا تُنفذ اتصالات خارجية، وبالتالي لم تُصمم بعد دورة حفظ وتجديد رموز OAuth.
- يجب استخدام HTTPS وإدارة أسرار وخدمات مراقبة وتشفير احتياطي وأمن حاويات وCI/CD متدرج.
