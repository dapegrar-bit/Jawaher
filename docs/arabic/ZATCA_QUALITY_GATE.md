# بوابة قرار الإنتاج — ZATCA Quality Gate

**القرار الحالي: NO-GO — يمنع إرسال فواتير العملاء الحقيقيين وبيع التطبيق على أنه متوافق.**

## مستويات العمل

1. **Prep**: بيانات أساسية ومراجعة أخطاء أولية داخل النظام — تم تنفيذه.
2. **Simulation**: استخدام بيانات تجريبية مختصة وXML موقع خارج المشروع مع CSID محاكاة — تجهيز الكود فقط، لم يُختبر اتصال حي.
3. **Pilot**: اختبارات الانقطاع والازدواج والاسترجاع وتغير حالات التخليص/الإبلاغ وربط توقيع معتمد — لم ينجز.
4. **Production**: مزود أسرار مناسب، مفاتيح مستقلة لكل منشأة وEGS، تدقيق أمني ومحاسبي وضريبي، وموافقة قرار إطلاق — لم ينجز.

## ضوابط غير قابلة للتفاوض

- عدم اعتبار `HTTP 200` نجاحًا ضريبيًا دون قراءة حالات ونتائج الوثيقة.
- عدم تغيير وثيقة مرحّلة أو معتمدة مباشرة؛ استخدمي إشعارات وعمليات تدقيق مصممة حسب المتطلبات.
- الحفاظ على ICV/PIH بالضبط وفق مواصفات الهيئة ومنع تعدد تسلسلات غير مصرح بها.
- أي طلب فشل بسبب انقطاع شبكة قد يكون وصل إلى الهيئة؛ قبل تكراره يجب فحص الحالة وتطبيق منطق Idempotency وسجل المحاولات.
- لا يجوز الاحتفاظ بـOTP أو CSID Secret أو المفتاح الخاص داخل سجل الأحداث أو الاستجابات النصية.
- يجب منع إرسال أي مستند ضريبي حقيقي من وضع التطوير غير المحمي.

## اختبارات إضافية لازمة للفريق

- SDK validator: حالات بيع قياسية، مبسطة، إشعار دائن، إشعار مدين، 15%، صفرية مع السبب، إعفاء مع السبب، خصومات، دفعة مقدمة، عملات حسب الدليل.
- Security: تنازع فروع/شركات، مصادقة متعددة العوامل، تسرب CSID، تبديل وحدة EGS، رفض API بدون مالك، مراجع تغييرات.
- Reliability: اتصال مفقود، HTTP 400/401/403/429/500، تأخير، محاولات مكررة، مستندات متزامنة، شهادة منتهية.
- المالية: إعادة حساب الضريبة والتقريب وتطابق فاتورة UBL مع القيد والدفتر وVAT return.
