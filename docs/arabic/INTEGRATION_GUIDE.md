# جواهر جسر — دليل التكامل مع برامج المحاسبة

## ما نفذ بالفعل

تسجّل الواجهة والخادم بيانات خارجية تم تطبيع نوعها الأساسي في جدول `integration_staging`: المصدر، المعرف الخارجي، نوع المستند، حمولة JSON، والحالة. تمنع قاعدة البيانات تكرار `(company_id, provider, external_id, record_type)`، وتحتفظ بالبيانات منفصلة عن القيود الدفترية. **لا يتصل هذا المسار مباشرة بالبرامج المنافسة.**

## الطبقة الموحدة المطلوبة للتشغيل التجاري

1. موصل `WafeqConnector` بصلاحية `contacts.read` و`invoices.read`، مع OAuth2 للمستخدمين المتعددين وحفظ الرموز مشفرة لكل منشأة.
2. موصل `XeroConnector` باستعمال OAuth2 ونطاقات الصلاحية الجديدة المعلنة بعد مارس 2026 ومراعاة حدود التطبيقات وخطط الاشتراك.
3. موصل `ERPNextConnector` باستعمال Frappe REST مع بيانات اعتماد مؤسسة العميل.
4. موصل `OdooConnector` بحسب إصدار النظام وبنية API المدعومة في خطة العميل.
5. موصل `SmaccConnector` بعد الحصول على وثائق الوصول والاتفاق التجاري الملائم.
6. موصل ملفات `CSV/XLSX` مع اختيار الأعمدة، وفحص العملات، وكشف المكرر، وحفظ المعرف الأصلي.

## ضوابط أساسية

- اعتماد نظام محاسبي واحد كمرجع معتمد لكل نوع مستند قبل أي كتابة متبادلة.
- تشفير Tokens والمفاتيح في خادم المؤسسة وعدم تمريرها للمتصفح أو تخزينها نصًا مكشوفًا.
- تأكيد المنظمة المرتبطة بالحساب خلال OAuth وعدم ربطها برقم يدخله المستخدم بحرية.
- إضافة `idempotencyKey` وتسلسل الإصدارات وأحداث الإنشاء/التعديل/الإلغاء.
- التعامل مع `429`, `401`, `403`، و`5xx` بالجدولة والمحاولات المنضبطة.
- سجل كامل لما تمّ سحبه وتحويله واستبعاده، وتقرير مقارنة بالأرقام قبل اعتماد أي نقل.
- عدم استقبال أو نشر معلومات مالية تتجاوز صلاحية العميل.
